# Support synthetic adapter, default off, no production entrypoint

This candidate extracts the supplied v4 claim/delivery functions into an importable module. It has no app route, scheduled worker, FCM integration, env credential or automatic execution. The only enqueue adapter rejects all but synthetic.acceptance and a synthetic-prefixed identifier, defaults disabled and uses the caller's transaction. It is not a production authorization boundary.

## Deliberate extraction correction
v4's claim() inserts current recipients on EVERY reclaim, contradicting its documented claim-time snapshot. This extraction snapshots only when claim_seq=1. Focused adapter coverage verifies retry/reclaim cannot append newly registered tokens. This does not solve lease expiry while an old send is in flight, or crash after external send before ledger commit. At-least-once only, duplicates remain possible.

## Current source integration boundary
Accepted source has native support token registration (/api/fcm-subscriptions, audience support), platformAuthority check and support subscriptions. Non-native Support registration intentionally returns unconfigured. firebase-messaging.ts has a private sendOne supporting /platform, but no exported Support dispatcher/caller. There is no production outbox in this extraction. Do not hook order.created/transfer-submitted based on prototype assumptions.

Before a target-only schema can be run:
- Validate existing platform_admins/support_fcm_subscriptions shapes, policies and role ACLs against current source, not prototype mock tables.
- Review dedicated sender role's exact SELECT/DELETE subscriptions, SELECT admins, outbox/recipient write grants and FORCE RLS policies. No grant to read tenant business data.
- Replace arbitrary event-id/kind definer admission with server-derived/actor+tenant-validated business admission when event semantics are grounded. v4's broad tenant-callable enqueue accepts arbitrary event kinds/IDs; copying it into production could permit alert spam or guessed-ID dedup poisoning. This extraction allows only synthetic events at the caller, not a sufficient production SQL restriction.
- Pin definer search_path to pg_catalog,pg_temp and qualify every object; source prototype search_path=gymos requires separate scrutiny. No postgres ownership assertion accepted blindly.
- Add target guard and supported role bootstrap, bounded transactions, rollback/dispose on all exceptional paths. Claim/finalization now attempt ROLLBACK on exceptions; caller still owns disposal and needs bounded connect/query/commit handling before provider use.

## Secret/process boundary
Run sender as a separate standalone process/worker using its restricted database identity and only its token decryption key and scoped FCM identity. The app only holds runtime identity and calls approved enqueue in the business transaction. Do not import sender code or sender credentials into the tenant-facing Next deployment. No new hosting is assumed: a one-shot local isolated worker with injected fake transport can prove adapter/provider mechanics without service credentials or scheduler. Later real delivery requires an approved non-commercial-terms-compliant worker host and device-scoped send scope; no money or new account is authorized.
