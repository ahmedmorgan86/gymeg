## نتيجة إعادة التقييم في 5 نوفمبر 2026

- أعيد تشغيل فحوص TypeScript وESLint وبناء Next.js واختبارات الوحدة والتكامل وبناء Windows وفحص اتساق الإصدارات؛ اجتازت جميعها. سبعة اختبارات قاعدة بيانات اختيارية لم تُشغّل لعدم وجود اتصال اختبار آمن، وفحص توقيع APK التشفيري لم يتوفر لغياب `apksigner`.
- فحوص الإنتاج لهذه الجولة أكدت أن health و`/api/member-session` يعيدان 200 وتظهر الفروع، والصفحات العامة وصفحات التطبيقات تفتح. رابط تنزيل Windows كان يعرض 1.1.15 رغم أن GitHub لا يحتوي إصدارًا بهذا الوسم، ثم يرجع فعليًا إلى 1.1.14.
- عولج التضارب في المصدر: أصبح الموقع يعرض الإصدار المنشور المتحقق 1.1.14، مع تمييز 1.1.15 كمرشح مصدر حتى نشر ملفه. أضيف فحص يمنع اختلاف الإصدار الظاهر عن رابط الرجوع، واختبار للحالتين.
- لم يُنشأ إصدار Windows 1.1.15 أو يُرفع ملفه في هذه المراجعة. لذلك لا يتضمن التحميل العام تحسينات Windows الموجودة فقط في المصدر 1.1.15. هذا هو القيد التجاري الأهم المتبقي في التوزيعة.
- ما زالت ملاحظات Supabase الحية الموثقة تحتاج معالجة منفصلة ومراجعة أمنية: حماية كلمات المرور المسرّبة معطلة، وامتداد `pg_net` ظاهر في `public`، إضافة إلى تنبيهات أداء وسياسات مكررة. لم تُغيّر قاعدة الإنتاج.

## الفحوص المحلية

- `npm run typecheck`: ناجح.
- `npm run lint`: ناجح.
- `npm run build`: ناجح، بما في ذلك تجميع Next.js وتوليد الصفحات.
- `npm run test:all`: 278 اختبار وحدة ناجحًا، و7 اختبارات اختيارية متصلة بقاعدة البيانات متخطاة، و16 مجموعة تكامل ناجحة.

- فحص التوقيع التشفيري لـAPK لم يكتمل: لا يوجد Android SDK أو `apksigner` في بيئة العمل. اجتياز اختبار البيانات والبصمة لا يساوي التحقق من شهادة التوقيع نفسها.
- فشل التشغيل الأول للاختبارات بسبب منع إنشاء العمليات الفرعية داخل العزل؛ بعد إعادة التشغيل المسموح بها نجحت المجموعة كاملة. وصُححت توقعات إصدار قديمة في اختبارَي Android.

## نتائج Supabase الحية — قراءة فقط

ظهرت بتاريخ 5 نوفمبر 2026:

- تحذيران أمنيان: امتداد `pg_net` موجود في schema `public`، وحماية كلمات المرور المسرّبة معطلة في Supabase Auth.
- 42 ملاحظة أداء لسياسات RLS حول إعادة تقييم `current_setting()`/دوال auth لكل صف.
- 6 مجموعات سياسات permissive متعددة، و7 فهارس بلا استخدام في إحصاءات الفترة.

لم تُحذف الفهارس، ولم تُغيّر سياسات RLS أو إعداد Auth مباشرة. أي تغيير في السياسات يتطلب migration مُراجعًا، واختبارات صلاحيات وعزل أندية على قاعدة اختبار قبل تطبيقه على الإنتاج. انظر روابط الإصلاح الرسمية في [مراجعة Supabase](SUPABASE_REVIEW_2026-10-28_AR.md).

- تثبيت التطبيقات الثلاثة وتحديثها على أجهزة Android فعلية، واختبار صلاحيات الإشعار ووصول FCM بعد إغلاق التطبيق.

لا تمثل نتيجة فحص الإصدارات أو نجاح الاختبارات البرمجية اعتمادًا تجاريًا للأجهزة أو مزودي الخدمة. لا تُرسل رسائل أو مدفوعات حقيقية في الاختبارات الآلية. لم تُختبر الأجهزة الفعلية أو مزودو الرسائل والموسيقى في هذه الجولة.
