This is a correctness candidate independent of allocation refs. It does not complete demand loading or reduce invoice scan work. The private scalar uses unchanged memberCredit over every owner invoice's allocations and voided fields, including unrelated rows that affect legacy JavaScript string arithmetic. Only the number is passed separately to memberView; foreign invoice payloads are never added to returned portal state. Account invoices/payments remain own-member only.

Live owner version is read before hydration and rechecked before/after money, with metadata revision matched to hydrated revision.
